- [ ] L05 — User Story ба Acceptance Criteria

User Story гэж юу вэ?

User Story нь хэрэглэгч системийг ашиглан ямар үйлдэл хийхийг хүсэж байгааг энгийн хэлбэрээр тодорхойлдог.

Ерөнхий бүтэц:

As a [хэрэглэгч], I want [үйлдэл], so that [зорилго].

User Story

US-01 Бараа бүртгэх

Агуулахын няравын хувьд би шинэ бараа бүртгэхийг хүсэж байна. Ингэснээр агуулахын барааны мэдээллийг системд хадгална.

Acceptance Criteria:

Шинэ SKU амжилттай бүртгэгдэнэ.
Ижил SKU давхар бүртгэгдэхгүй.
Барааны нэр хоосон байвал алдаа буцаана.

US-02 Бараа орлого бүртгэх

Няравын хувьд би барааны орлого бүртгэхийг хүсэж байна. Ингэснээр агуулахын үлдэгдэл нэмэгдэнэ.

Acceptance Criteria:
Орлогын тоо хэмжээ зөв байна.
Баталгаажсан орлого үлдэгдлийг нэмэгдүүлнэ.
Ноорог баримт үлдэгдлийг өөрчлөхгүй.

US-03 Бараа зарлага бүртгэх

Няравын хувьд би барааны зарлага бүртгэхийг хүсэж байна. Ингэснээр агуулахаас гарсан барааг хянана.

Acceptance Criteria:

Үлдэгдэл хүрэлцэж байвал зарлага хийгдэнэ.
Үлдэгдэл хүрэлцэхгүй бол зарлага татгалзагдана.
Сөрөг тоо хэмжээ хүлээн авахгүй.

US-04 Үлдэгдэл харах

Менежерийн хувьд би барааны үлдэгдлийг харахыг хүсэж байна. Ингэснээр агуулахын нөөцийг хянана.

Acceptance Criteria:

Барааны үлдэгдэл харагдана.
Бараагаар болон агуулахаар шүүж болно.
Үлдэгдэл 0 байсан ч бараа харагдана.

US-05 Баримт баталгаажуулах

Няравын хувьд би орлого, зарлагын баримтыг баталгаажуулахыг хүсэж байна.

Acceptance Criteria:

Баталгаажсан баримтыг дахин засахгүй.
Нэг баримтыг давхар баталгаажуулахгүй.
Үлдэгдлийн өөрчлөлт нэг үйлдлээр хийгдэнэ.

US-06 Буцаалт хийх

Менежерийн хувьд би буруу хийгдсэн гүйлгээг буцаахыг хүсэж байна.

Acceptance Criteria:

Буцаалтын баримт үүснэ.
Нэг баримтыг олон удаа буцаахгүй.
Эх баримттай холбоос хадгалагдана.

US-07 Нэвтрэх ба эрх шалгах

Администраторын хувьд би хэрэглэгчийн эрхийг удирдахыг хүсэж байна.

Acceptance Criteria:

Нэвтрээгүй хэрэглэгч хамгаалагдсан үйлдэл хийхгүй.
Зөвхөн харах эрхтэй хэрэглэгч мэдээлэл өөрчлөхгүй.
Эрхтэй хэрэглэгч өөрийн үүргийн дагуу үйлдэл хийнэ.

US-08 Үйлдлийн түүх харах

Менежерийн хувьд би системд хийгдсэн үйлдлийн түүхийг харахыг хүсэж байна.

Acceptance Criteria:

Үйлдэл хийсэн хэрэглэгч харагдана.
Үйлдлийн огноо, цаг хадгалагдана.
Нууц үг болон token хадгалахгүй.

Миний дүгнэлт

Энэ хичээлээр хэрэглэгчийн хэрэгцээг User Story хэлбэрээр бичиж сурсан.

Мөн Acceptance Criteria ашиглан тухайн шаардлага амжилттай биелсэн эсэхийг шалгах нөхцөлийг тодорхойлсон.

L05 шалгалт
